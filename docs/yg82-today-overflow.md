# YG-82 오늘 화면 넘침 검증

운영 데이터 없이 로컬 Vite의 `/api/*` 요청을 Playwright 응답으로 대체했다. fixture에는 긴 제목, 키, 대기 사유와 메타, 시간 지정 일, 밀린 일을 넣었다. POST와 실패 응답도 가상 응답이다.

- 수정 전 1100×800: 본문 그리드 오른쪽 1076px, 밀린 일 패널 오른쪽 1096px. 최소 열 너비와 간격 864px이 가용 844px을 넘었다.
- 긴 밀린 일 제목을 넣은 수정 전 1099×800: 문서 scrollWidth 2728px. 패널 바깥 grid 자식의 최소 콘텐츠 너비가 원인이었다.
- 768×800 hover: 빠른 조작과 배지가 제목을 압축했다. 제목 폭 100px 이상과 조작 버튼의 패널 경계를 검사하는 테스트가 수정 전 실패했다.
- 수정 후 `node test/yg82-browser.mjs`: 390, 719/720, 767/768, 1099/1100/1119, 1199/1200, 1280×800, 1366×768, 1440×900에서 문서 가로 너비와 패널 경계 확인. 긴 제목, hover, coarse pointer 에뮬레이션, 모바일 탭, 최근 추가 후 조회 오류와 타임라인 범례 접근을 검사했다. 스크립트는 로컬 Vite 5174 포트 또는 `YG82_BASE`를 사용한다.
- Chrome for Testing에서 임시 확장의 `chrome.tabs.setZoom(1.25)`으로 실제 페이지 확대를 적용했다. 1280×800 → innerWidth 1024, 1366×768 → 1093, 1440×900 → 1152, 각 devicePixelRatio 1.25; 세 경우 문서 scrollWidth는 innerWidth와 같고 밀린 일 패널은 그리드 안에 있었다. 확대 화면은 `/tmp/yg82-zoom-{1280,1366,1440}.png`에 남겼다.
- 세로 문서 스크롤은 허용한다. 긴 상단 알림이 있을 때도 범례까지 스크롤할 수 있음을 확인했다. 전체 페이지 `overflow:hidden`이나 sticky 변경은 사용하지 않았다.

실물 터치 기기와 다른 브라우저 엔진은 검사하지 않았다. 격리 fixture의 화면과 조작 검사는 운영 데이터의 실제 분포를 보장하지 않는다.
