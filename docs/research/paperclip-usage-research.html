Paperclip capability research · 2026.09

AI 에이전트의 일을 운영하는 Control Plane

Paperclip이 무엇을 맡고, 사람들이 어떤 흐름으로 사용하며, Yggdrasil에서는 어디까지 재사용하는 것이 좋은지 정리했다.

핵심 결론

Paperclip은 Yggdrasil 전체가 아니라 Agent 실행과 운영을 담당하는 하부 엔진으로 보는 것이 적절하다.

01 · Definition

Paperclip은 무엇인가

Codex나 Claude Code 자체가 아니라, 여러 AI 에이전트에게 일을 배정하고 상태·결과·비용·승인을 관리하는 운영 계층이다.

02 · Common patterns

대표적인 세 가지 사용 방식

공개된 사용자 통계가 아니라, 공식 문서와 번들 팀 템플릿에서 확인되는 대표 운영 패턴이다.

1

직접 작업 배정

사람이 Issue를 만들고 Codex에게 할당한다. Paperclip은 실행, 세션, 결과와 비용을 기록하고 사람은 결과를 검토한다.

  • 여러 AI 터미널을 한곳에서 관리
  • 작업별 문맥과 결과 유지
  • 현재 우리에게 가장 적합한 시작점
2

CEO가 자동 위임

사람이 목표만 정하면 CEO 에이전트가 전략을 제안하고, 승인 후 CTO·개발자·디자이너에게 작업을 분해해 배정한다.

  • 목표에서 작업까지 계층적으로 연결
  • 전략과 채용에 인간 승인 적용
  • 초기 개인 사용에는 다소 무거움
3

반복 업무 자동화

Routine이 예약 시간마다 Issue를 생성하고 담당 에이전트를 깨운다. 실행 결과는 일반 작업과 동일하게 추적된다.

  • 주간 진행 상황 요약
  • GitHub Issue·품질 점검
  • 리서치·콘텐츠 계획 반복

03 · Strongest use cases

현재 가장 강한 활용 영역

공식 저장소에 포함된 팀 카탈로그를 보면 소프트웨어 개발이 가장 구체적으로 설계되어 있다.

활용 영역 대표 팀 주요 결과물 적합도
소프트웨어 개발 CTO + Senior Coder + QA 코드, PR, 테스트, 검증 보고 매우 높음
제품 디자인 Principal Product Designer 와이어프레임, UX 검토 높음
콘텐츠 운영 Content Lead 콘텐츠 캘린더, 초안 보통
반복 운영 담당 Agent + Routine 정기 보고서, 점검 결과 높음
다중 Agent 관리 CEO + 전문 Agent 위임, 승인, 비용 통제 규모가 생기면 높음

04 · Runtime

Heartbeat가 작업을 움직인다

에이전트는 항상 실행되지 않는다. 할당, 예약, 호출, 댓글, 승인 처리 같은 사건이 생기면 짧은 실행 구간으로 깨어난다.

Paperclip이 대신 해결하는 어려운 부분

동일 작업의 중복 실행 방지, Codex·Claude 세션 재개, 실행 비용 귀속, 실패 복구, 승인 대기, 에이전트별 비밀값과 권한 관리를 한 흐름으로 묶는다.

05 · Data

쌓이는 것은 학습 데이터가 아니라 운영 기록

오래 모아야 제품이 동작하는 데이터셋이 아니다. 첫날부터 쓰고, 기록이 늘수록 운영 판단의 근거가 생긴다.

  • 회사, 목표, 프로젝트와 Issue
  • Agent 역할, 설정과 보고 체계
  • Run, Session과 실행 이벤트
  • 댓글, 문서, 첨부와 결과물
  • 모델·Agent·작업별 비용
  • 승인, 거절, 실패와 재시도

기록으로 알 수 있는 것

어떤 작업을 AI가 잘 처리했는지, 어떤 지시에서 반복 실패했는지, 사람의 개입 지점과 작업당 비용이 어느 정도인지 파악할 수 있다.

기록이 해결하지 않는 것

개인 메모의 의미 구조, 자유로운 문서 탐색, 장기 지식의 연결은 Paperclip 기록만 쌓는다고 자동으로 해결되지 않는다.

06 · Product boundary

Notion이나 Nexus를 그대로 대체하지는 않는다

Paperclip은 task와 agent 실행 중심이다. 문서와 지식을 제품의 중심 객체로 다루는 경험은 상대적으로 얇다.

Paperclip이 잘하는 것

  • Agent 등록과 역할 분리
  • 작업 할당과 실행 상태 추적
  • Run·Session·Heartbeat 관리
  • 비용·승인·감사 기록
  • Codex·Claude·외부 runtime 연결

Yggdrasil이 보완할 것

  • 문서 트리와 빠른 메모
  • 개인 지식 검색과 연결
  • 아이디어에서 의사결정까지의 흐름
  • 제품 발견과 장기 맥락
  • 사람 중심의 단순한 개인 UX

07 · Yggdrasil direction

추천 구조

Paperclip을 전부 다시 만들거나 Yggdrasil 전체로 삼지 않고, 이미 잘 만든 실행 계층으로 활용한다.

Knowledge layer Notion 같은 문서 · 메모 · 검색 · 연결 · 의사결정
Product layer Nexus·Linear 같은 Product · Goal · Issue · 진행 상황
Execution layer · Paperclip Agent · Run · Session · Heartbeat · Approval · Cost · MCP

지금 만들지 않을 것

Nexus 전체 복제, 자체 checkout·run·session 구현, 복잡한 CEO 조직도, 장기 확장을 위한 플러그인 시스템은 아직 필요하지 않다.

08 · First evaluation

우리의 첫 사용 시나리오

CEO·CTO·QA 조직부터 시작하지 않고, 사람과 한 명의 Builder 사이 작업 흐름을 먼저 검증한다.

Company Yggdrasil
Goal 개인용 AI-native workspace의 첫 버전을 정의한다
Agent Builder · Codex adapter · Yggdrasil workspace
첫 작업 제품 정의, Notion 기능 분류, Paperclip 중복 영역 확인, 작은 기능 하나 구현
평가 기준 작업 생성부터 실행·검토·재개까지 자연스러운가, 직접 구현하지 않아도 될 영역이 무엇인가
